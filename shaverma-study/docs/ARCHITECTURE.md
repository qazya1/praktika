# Архитектура упрощённой системы

## Прикладная подсистема

`backend` содержит бизнес-логику и является единственным владельцем данных. Она отвечает за:

- проверку авторизации клиента и сотрудника;
- выдачу меню;
- расчёт суммы и создание заказа;
- хранение снимка названия и цены позиции в заказе;
- проверку ролевых переходов статуса;
- передачу события о новом заказе в управляющую подсистему.

## Управляющая подсистема

`manager` не изменяет заказ напрямую. Она отвечает за взаимодействие с внешними платформами:

- получение событий Telegram/MAX;
- выдачу пользователю ссылки запуска мини-приложения;
- отправку уведомлений сотрудникам о новых заказах.

Связь подсистем выполняется через HTTP с заголовком `X-Internal-Key`. Такое разделение позволяет заменить мессенджер или отключить его без изменения логики заказов.

## Данные

- `users` — пользователи Telegram/MAX;
- `staff` — сотрудники и роли;
- `products` — меню;
- `orders` — заказ, источник, клиент, статус, сумма;
- `order_items` — снимки позиций заказа.

## Роли

- `cashier`: перевод `new → cooking`, `ready → completed`, отмена активного заказа;
- `cook`: перевод `cooking → ready`;
- `director`: все штатные переходы и отмена.

## Защита Mini Apps

Backend принимает только исходную строку `initData`, сортирует параметры, формирует строку проверки и сверяет HMAC-SHA256 с бот-токеном. Дополнительно проверяется `auth_date`. Режим `dev:` разрешён только при `DEV_AUTH=true`.
